# harness

Multi-axis control that keeps a configuration from collapsing back to ambient preference.

A harness is not a single force. It is a coordinated set of constraints (energy, geometry, information density, field conditions, etc.) that continuously re-supply whatever is load-bearing for a non-default density or topology.

The soap-bubble case is the minimal example: what must be maintained so the interface does not pop? Scaling that question up to volume-scale, room-like, or planetary-scale sustained pathways is the longer interest.

This folder holds attempts to formalize and eventually code those constraint systems.
